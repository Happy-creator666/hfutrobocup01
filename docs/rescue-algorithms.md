# 救护算法改进与验证

本次修改以 `de8eb62` 为对照版本。修改的是救护车（AT）的决策策略，
以及救护、消防、警察共用的 A* 寻路正确性；没有改变比赛服务器的计分规则。
原有消防队挖掘、救护车装载和运输的职责划分保留。

## 六项改动

| 改动 | 主要文件 | 行为变化 |
| --- | --- | --- |
| 1. 按救援完成时间选人 | `RescuePolicy.java`、`AmbulanceDecisionTool.java`、`AtExecutor.java` | 不再按“剩余生命少于 20 轮就放弃”筛选，也不直接装载集合中的第一个人。先判断能否完成，再按紧迫程度、耗时和信息新旧排序。 |
| 2. 避难所选择 | `AmbulanceDecisionTool.java` | 综合通行成本、近期空床位、排队人数和未知信息的惩罚；排除明确床位容量为零的避难所。 |
| 3. 建筑目标选择 | `AtTargetProvider.java`、`AmbulanceDecisionTool.java` | 已知伤员按可救人数、紧急程度和耗时计分，人数提供适度加分；探索单独计分；分区是偏好，跨区紧急报告也能进入候选。重复目标按 ID 合并。 |
| 4. 多车协作与挖掘衔接 | `AtMediator.java`、`AmbulanceDecisionTool.java` | 按预计可救人数决定需要多少车；只接受近期任务消息；按预计到达时间、再按 ID 决定优先权；排除已知死亡、被埋、载人的队友。预测消防挖掘时，人员在预计到场后才贡献工作量。 |
| 5. 稳定目标与安全复用 | `AmbulanceDecisionTool.java`、`AreaPassableTool.java` | 小幅优势不立即换目标；明显更优、任务失效或持有期结束时可以切换。只短期复用已选路线；通行性变化、路径区域有新观测、超期或当前位置离开路径时重新计算。 |
| 6. 寻路正确性与预算 | `AStarSearch.java`、`SearchPathTool.java` | 不再依赖优先队列中可变的外部距离；允许更优路线重新入队并跳过旧条目。默认启发值使用到最近目标边的欧氏距离下界，而非目标集合中心。救护规划限制候选、搜索次数、展开节点和时间。 |

`AmbulanceDecisionTool` 通过项目已有的 `@HfutTool` 自动发现机制加入每个 AT 的工具链。
目标提供器和竞争判断器调用同一个决策工具，因此共享本轮搜索缓存和预算，
而非分别重复寻路。每辆车只使用自身世界模型和收到的消息，不读取其他智能体的私有状态。

## 如何判断是否来得及

所有时间都以“模拟轮次”为单位，不是现实秒数。

```text
预计完成 = max(车辆到达时间, 消防挖掘完成时间)
           + 1 轮装载 + 预计运输/排队时间 + 1 轮卸载

可救条件 = 预计完成 + 安全余量 <= 预计剩余生命
           且预计完成 <= 比赛剩余轮数
```

只在可救任务中比较启发式分数：耗时越短越有利、生命余量较少适度加急、
较旧的生命信息降低可信度。建筑中可救人数以平方根形式加分，避免人多就无限压过紧急程度。
本项目的生命估计、距离折算和排队等待均有误差，该分数不是经标定的存活概率。

当前区域的装载使用精细寻路估算运输成本；远处建筑先使用便宜的直线距离粗估，
只对少量候选计算实际通行成本。精细路线仍是当前已知地图下的估计，
未知堵塞、队员后续改目标和避难所未来变化都可能改变结果。

## 超预算与无法到达有区别

```text
FOUND       → 使用路线，发出移动请求
UNREACHABLE → 本次搜索已完成但没有路线，可以暂时记录目标受阻
DEFERRED    → 计算预算不足，推迟评估；不能据此发送“道路堵塞”的结论
```

后面的候选即使不能再发起新搜索，也允许使用本轮已经算好的路线。
单次搜索超预算的目标短暂退让，粗选名单的一部分轮换，避免固定目标一直占用预算。
避难所优选项全部失败时，在预算内继续尝试更远选项，尾部也轮换。
这不保证有限预算内遍历全地图；尤其大地图需要根据决策耗时记录调整参数。

路线复用最多从原始计算时刻起保留 3 轮，复用不会刷新有效期；
保留原路线的保守耗时估计，实际移动前仍经过既有道路通行检查。
生命周期收尾记录本轮真正采用的目标与路径。

另外修正了执行流程中的几个相关问题：

- 卸载成功以新一轮观测为准；上轮发出卸载请求不等于已经卸载，不能手动改写伤员位置。
- 装载失败的伤员短暂冷却后允许重试。
- 筛人时复制位置工具的集合，避免删除自己时改坏公共索引。
- 三轮休息后的移动兜底只在空车且没有有效行动时生效。
- “暂时没有伤员”信息本地和消息接收端都使用有限等待时间；新伤员报告可覆盖旧无伤标记。
- 真正完成搜索但不可达的目标会暂时记录受阻；修复了首次记录时提前返回、没有进入本轮观察集合的问题。
- 预计算格式升级为 2，旧缓存走正常准备流程，避免新增工具缺少完成记录。

## 默认参数

参数集中在 `config/params.properties` 的 `AmbulanceDecisionTool.*` 下，可用于比赛前调参：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `safetySteps` | 3 | 生命判断预留轮数 |
| `travelTimeFactor` | 1.3 | 通行成本折算轮次的保守系数 |
| `informationTtl` / `claimTtl` | 10 / 5 | 避难所信息新鲜期、队友任务声明新鲜期 |
| `rendezvousLeadSteps` | 5 | 到达后最多允许的预计挖掘等待 |
| `maxResponders` | 8 | 单点救护车需求上限 |
| `queueStepsPerPerson` | 3 | 每个排队者的估计等待惩罚 |
| `unknownRefugePenalty` / `fullRefugePenalty` | 4 / 15 | 未知/过期信息和满床的惩罚 |
| `outsidePartitionPenalty` | 2 | 分区外目标的小幅惩罚 |
| `targetHoldSteps` / `switchImprovement` | 10 / 0.2 | 目标保持窗口及换目标所需改善比例 |
| `routeReuseSteps` / `loadRetrySteps` | 3 / 2 | 路线最长复用时间、装载失败冷却 |
| `coarseCandidates` / `candidatesToRefine` | 64 / 4 | 空车粗选数量、精算候选数量 |
| `refugesToRefine` | 3 | 优先精算避难所数；全部失败时可继续尝试 |
| `maxSearchesPerCycle` | 8 | 每车每轮最多发起的规划搜索 |
| `maxExpansionsPerSearch` | 6000 | 单次搜索展开节点上限 |
| `planningMillis` | 60 | 搜索阶段墙钟时间预算，还会受本轮剩余思考时间限制 |

时间预算是规划搜索的截止检查，不能等同于整个智能体思考过程的硬截止；
消息处理、几何检查、其他工具及调试开销仍需要实测。
旧 `AtTargetProvider.*`、`AtMediator.*` 及 `AtExecutor.ignoreTimeToDead` 参数不再用于新救护决策。

## 验证与比赛前对比

使用 JDK 17。常规命令为 `.\gradlew.bat test`。
原依赖无法下载时，按 `runtime-validation.md` 的官方标签源码验证方式执行：

```powershell
.\gradlew.bat test --offline --no-daemon --init-script tools/verify-upstream.init.gradle
```

2026-10-25 使用上述官方标签源码验证方式编译通过，44 项测试全部通过（0 失败、0 错误）。
原始二进制依赖的常规构建方式仍受 `runtime-validation.md` 所述依赖可获取性限制。

新增测试覆盖：短生命但可救、长生命但来不及、比赛结束约束、紧迫程度/信息可信度、
满床排队、第四个避难所可达、跨分区伤员、旧无伤标记被新伤员覆盖、队伍需求、
过期/死亡/载人队友排除、消防到达后再计挖掘工作、目标保持和切换、
路线缓存原始有效期、通行性变化、共享搜索预算、装载与卸载请求、
预算不足不能报堵、预算耗尽后使用缓存路线。
寻路另用固定随机种子的 150 组图，与独立 Bellman-Ford 结果逐一对照。
这些测试验证代码行为；仿真场景的寻路耗时由替身控制，不代表真实地图的运行速度。
